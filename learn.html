01 / MINIMUM MATHEMATICS

先补能动手计算的数学

不需要先读完抽象代数。入门阶段先会算四件事：向量的整数线性组合、内积、长度，以及模 q 的余数。把 (3,4) 的长度算成 5，把 96 mod 97 看成靠近 0 的 −1，就能读懂后面的距离与噪声。

格中的基向量必须乘以整数再相加；LWE 中的公开方程则在模 q 的世界里计算。这是两种不同的数学视角，不要把图上的几何点直接当成 ML-KEM 密文。

02 / LATTICE IS A SET

格不等于它的一组基

给定线性无关的基向量 b₁,…,bₙ，允许沿每个方向走任意整数步，所有能到达的点构成格。这个点集不依赖唯一的坐标描述。例如 (1,0),(0,1) 与 (1,0),(6,1) 都能生成二维整数格 ℤ²：第二组可以用整数加减重新得到第一组。

“好基”短且较接近正交，“坏基”长而倾斜。同一个格的不同基可以让某些近似解码方法表现差很多。这个图像非常适合解释早期 GGH 方案；不能把现代 ML-KEM 简化为“公钥是一组坏基、私钥是一组好基”。

03 / PROBLEMS, NOT PICTURES

SVP、CVP、BDD：三个问题，三个输入

SVP

在格中找一个非零、尽可能短的向量；原点本身不算答案。

CVP

给一个任意目标点，找离它最近的格点。

BDD

给一个承诺离某格点很近的目标，尝试正确解码。

在二维图上可以目测，在高维通常不行。但“高维”本身不是安全证明：近似程度、维度、模数、噪声分布、特殊结构与攻击算法都会改变成本。格密码的安全分析会把具体方案关联到具体困难问题，而不是只说“最近点很难”。

合法解密可借用 BDD 的直觉：目标被小噪声推离可区分区域的中心，密钥让接收者消去主要结构再判断它更接近哪里。这是教学类比，不是所有格密码方案的正式定义。

04 / THE ATTACKER'S TOOLBOX

LLL 会改善一组基，但不会破解一切

LLL 反复用 Gram–Schmidt 投影衡量倾斜程度，进行整数倍消去和相邻交换，得到较短、较接近正交的基。它有多项式时间保证，但不保证总能找出真正最短向量。BKZ 在局部块里做更强的规约；通常块越大，解的质量越好，计算成本也越高。

做 CTF 时，先找“小未知量”：泄漏的 nonce 位、RSA 因子的部分信息、低密度背包或可恢复的小分式。建模成格后，规约才有机会找回信息。这些题目多数不是对标准参数 ML-KEM 的攻击。真实安全估计还要比较 primal、dual 等攻击以及所用的成本模型。

动手顺序

先运行 LLL 小例子 ↗，比较规约前后的向量长度；再选做 CTF 建模指南 ↗。不要把 LLL 的成功率当成标准参数安全评估。

05 / NOISY LINEAR ALGEBRA

LWE 与 SIS：同一张地图上的两种问题

如果公开足够多无噪声方程 b = As mod q，恢复秘密 s 通常是线性代数。LWE 在每个方程中加入小误差 e。攻击目标可以是恢复 secret（search-LWE），也可以是区分这些样本和随机数据（decision-LWE）。安全依赖参数与误差分布，绝不是“随便加一点噪声就安全”。

LWE：b = As + e (mod q)　｜　SIS：找短 x ≠ 0，使 Ax = 0 (mod q)

SIS 要求找一个短的模关系；去掉“短”这个要求，模线性方程常常有许多容易得到的解。它在哈希、承诺和签名设计中很重要。LWE 和 SIS 有不同的输入与目标，但都把“短 / 小”变成问题的关键约束。

toy 加密常把 bit 0 放在 0 附近，把 bit 1 放在 ⌊q/2⌋ 附近。合法方消去与 secret 相关的项后，若残余噪声不足以跨越解码边界，就能恢复 bit。错误太小可能伤害安全，错误太大则可能导致解密失败。

推导一次正确性

若 u=Aᵀr、v=bᵀr+bit·⌊q/2⌋、b=As+e，则 v−sᵀu = eᵀr+bit·⌊q/2⌋ (mod q)。在 噪声交互模型 ↗ 观察跨过边界时的错误。

06 / STRUCTURE FOR EFFICIENCY

从 LWE 到 Ring、Module 与 NTRU

普通 LWE 可以涉及较大的矩阵。把运算放到多项式环，例如 ℤq[x]/(xⁿ+1)，能用多项式乘法紧凑表达大量线性关系。Ring-LWE 使用更多环结构；Module-LWE 可看作在结构与表达能力之间的一种折中。结构提高效率，也改变了要分析的问题与攻击面。

NTRU 是另一条有悠久历史的多项式与格路线，不能简单说成“换了名字的 LWE”。读方案时要问：公钥和私钥是什么、依赖哪个问题、参数如何影响失败概率与攻击成本、是否需要 NTT 或其他快速多项式运算。

普通 LWE

结构较少，矩阵表示可能较大。

Ring-LWE

更多环结构，表示和乘法更紧凑。

Module-LWE

模块结构，是 ML-KEM 理解入口。

07 / FROM PROBLEM TO SCHEME

标准不是把 toy LWE 放大几倍

ML-KEM 是密钥封装：生成密钥对、用公钥封装产生密文和共享秘密、用私钥解封装得到共享秘密。FIPS 203 将其安全性关联到 Module-LWE，给出 ML-KEM-512、768、1024 三个参数集。它不能单独完成对端身份认证，也不是任意长消息加密接口。

ML-DSA 是模格数字签名：生成密钥、签名、验证。它的安全目标是防伪造，接口不能与 KEM 混用。真正的标准还规定字节编码、采样、拒绝采样、失败处理与诸多细节；教学脚本没有这些性质。

FIPS 205 的 SLH-DSA 是基于散列的签名，不属于格基；NIST 还在推进其他路线。格是 PQC 的重要分支，但“抗量子 = 格密码”并不成立。

读标准时的顺序

先看用途与接口，再看参数集和数据尺寸，然后看正确性与安全要求；最后才进入多项式表示、NTT 和精确伪代码。

08 / OPTIONAL DEEP DIVES

选一个方向深入，不必一次学完

全同态加密允许在密文上计算；许多方案利用格相关构造，学习时关注运算导致的噪声增长、模数链和 bootstrapping。BFV/BGV 面向精确算术，CKKS 面向近似数值计算。它们与 KEM 是不同用途的密码构造。

密码分析可沿 CTF 小根、HNP、背包走向真实参数估计，但必须分清“用格算法攻击旧密码的弱实现”和“攻击格基密码本身”。系统工程则要研究协议认证、硬件安全模块、侧信道、故障注入、证书尺寸与软件供应链。
